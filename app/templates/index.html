Security you can demonstrate

Every one of these is enforced on the server. The QR code is only a delivery mechanism — it is the token behind it that is protected.

AES-256-GCM at rest

Each file gets its own random key. That key is itself encrypted with a server master key that never touches the database.

Links that expire

From 10 minutes to 24 hours. After that the link returns a clear “expired” page and the encrypted bytes are shredded.

Optional password

Hashed with Argon2id, verified on the server, and every wrong guess is rate limited and written to the audit log.

One-time downloads

Consumed atomically, so two people scanning the same code at the same instant can never both receive the file.

Rate limited

Uploads, password attempts and downloads all have their own budgets, which is what makes a 256-bit token worth having.

Cleaned up automatically

A background sweep removes expired shares, consumed one-time files and any blob no record points at.

Four steps, about twenty seconds

Pick a file

Drag it in, or browse. Nothing leaves your machine until you press upload.

Set the rules

Expiry, a password if you want one, and whether the link dies after the first download.

Show the QR

The receiver points a normal phone camera at your screen. No app to install.

It cleans itself up

You can watch the countdown and the download count, or cancel the share early.
